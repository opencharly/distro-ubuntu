# 2026.296.1308 — fix(pins): the clawsweeper-review box pins the layer's pre-fix commit, and the corpus cannot be generated while it does

## Summary

The `clawsweeper-review` box pinned `layer-clawsweeper` at the commit **before** the
layer's skill node was fixed, and the marketplace corpus generator refuses that
content: the node carried an inline `description:` that disagreed with its
`SKILL.md` frontmatter, and `plugin-marketplace`'s `fillSkillFromFile` treats that
as two sources of truth for one published page and refuses the node.

The pin is advanced to the layer's release tag `v2026.296.1202` (merge
`65397ecb`), the commit that deleted the inline `description:` and left the
`SKILL.md` frontmatter as the single source of record.

The tag is also the form `charly box reconcile` realigns, and the only form the
corpus refresh's refs list advances — a commit-SHA pin is invisible to it, which
is why the daily refresh has been red and why the docs projection and the
umbrella's `marketplace` gitlink have been stuck behind it. That blindness is
filed as opencharly/marketplace#550; the producer half of this change is
opencharly/distro-ubuntu#57.

The diff is one file, `box/clawsweeper-review/charly.yml`, one line:

```diff
-            - '@github.com/opencharly/layer-clawsweeper/candy/clawsweeper-review:a9f48c9d4483370b4ef495c0d809c8fb17a71fbe'
+            - '@github.com/opencharly/layer-clawsweeper/candy/clawsweeper-review:v2026.296.1202'
```

(the comment above it is rewritten to say what the tag names and why).
