# 2026.225.1508 — re-stamp the schema version for the remove-candy-localpkg cutover

Two coupled edits, both required by the cross-repo `remove-candy-localpkg`
cutover (consuming spec `4cff4d0`).

- **The schema stamp.** `charly.yml` `version:` → 2026.225.1508, keeping this
  repo's schema marker aligned with the landed spec so the load-time gate
  accepts it under the post-removal schema.
- **The `check-ubuntu-debootstrap-vm` bed rewrite** (48 lines of `charly.yml`).
  Not incidental: the old bed asserted `dpkg -s opencharly`, which is
  impossible once the cutover removes the localpkg package install, so a
  stamp-only change would leave a bed that cannot pass. The bed is re-pointed
  at what the post-cutover deploy actually produces — the charly candy's copy
  step landing the binary at /usr/bin/charly. `localpkg-deb-autoresolve`
  (marker `LOCALPKG-DEB-AUTORESOLVE-OK`) becomes `charly-binary-installed`
  (`CHARLY-BINARY-OK`), a `welded-command-project-less` check is added
  asserting `charly doctor` reaches its `Summary:` line project-less from /tmp,
  and a `tailscale-package-installed` check (`TAILSCALE-PKG-OK`) asserts the
  package the bed's apt-repo cascade exists to deliver.

Every assertion is anchored on the MECHANISM rather than on charly merely being
reachable. The deploy stages its OWN host binary at a versioned `/tmp` path for
deploy use (`spec/exec/charly_install.go`, which never alters PATH), so an
unanchored `command -v charly` passes even when the candy installed nothing —
it cannot discriminate the install mechanism the step names. `test -x
/usr/bin/charly` can only be satisfied by the candy's `copy:` step. The same
reasoning drives the tailscale check: the `sources.list` grep proves the repo
was configured, not that the package landed.

The `add_candy` pin is repointed from the immutable pre-cutover tag
`v2026.201.0706` (whose charly candy carries the removed `localpkg:` map and no
`copy:` step — the bed's checks would have passed via the exact mechanism the
cutover deleted) to `v2026.226.1719`, the first post-cutover tag whose charly
candy lands the binary at `/usr/bin/charly` via its `copy:` step. The
`welded-command-project-less` probe runs `/usr/bin/charly doctor` — the
installed binary, not whatever `charly` resolves to on PATH.

The dropped `dpkg -s podman` / `dpkg -s libvirt-daemon-system` assertions are a
deliberate, disclosed reduction: they witnessed apt auto-resolving the `.deb`'s
`Depends`, a mechanism this cutover removes, and the composed layers still
install them.
