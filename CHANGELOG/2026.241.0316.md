# 2026.241.0316 — fix(tag-on-merge): install the current org-wide dispatcher - this repo cannot tag

## Summary

**This repo cannot produce release tags.** Every `tag-on-merge` run ends in `startup_failure`:

```
$ gh run list --workflow=tag-on-merge.yml --limit 4
  2026-08-29T01:09:14Z  schedule  startup_failure
  2026-08-28T22:34:36Z  workflow_run  startup_failure
  2026-08-28T22:34:33Z  workflow_run  startup_failure
  2026-08-28T22:34:31Z  workflow_run  startup_failure
```

Newest tag is `v2026.238.1348`, with **1 commit(s) merged since it** and therefore unreleased.
Consumers pinning this repo by tag cannot see them.

## Root cause

The org reusable workflow this dispatcher calls declares job-level permissions:

```yaml
# opencharly/.github/.github/workflows/tag-on-merge.yml
jobs:
  tag-and-changelog:
    permissions:
      contents: write
      pull-requests: read
```

A caller that sets an explicit `permissions:` block makes **every scope it does not list
`none`**, and a reusable workflow may not request more than its caller's ceiling — so the call is
rejected before any job starts. That is exactly `startup_failure` with no job to inspect. This
repo's dispatcher granted only:

```yaml
permissions:
  contents: write        # pull-requests is therefore `none`
```

Repos that tag successfully today (`marketplace`, `charly`) grant `pull-requests: read`.

The dispatcher was also **two revisions behind**: still on the `schedule` cron trigger the org
retired after measuring 21–44 minute delivery gaps with no SLA, rather than the event-driven
`workflow_run` + `push` form with the bounded `wait-for-merge` readiness probe.

## How tested

Installed **verbatim** — byte-identical to the copy running in repos that tag successfully:

```
$ diff .github/workflows/tag-on-merge.yml <marketplace>/.github/workflows/tag-on-merge.yml
$ echo $?
0
```

No local variation, deliberately: a forked dispatcher is how this drifted in the first place. The
diff against this repo's previous file is `+  pull-requests: read` plus the trigger and
readiness-probe revision.

**The proof is this PR's own merge** — a CalVer tag on the merge commit, where previous merges
produced none. Checkable directly; I will confirm on the merge commit rather than assert it here.

## Scope

explicit warning to that template about the `pull-requests: read` line, since dropping it fails
closed and silently.
