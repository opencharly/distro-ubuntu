# 2026.320.1426 — feat(ubuntu)!: retire the non-CachyOS coder bed and its image

## Summary

Retires `check-ubuntu-coder-pod` and the `ubuntu-coder` image it was the only deploy definition of,
with that image's skill and its routing node.

`ubuntu-coder` was a kitchen-sink developer-workstation demo — neither charly's own machinery nor a
package build — so it is one of the nine `pod:`/`vm:` definitions the org's non-CachyOS retirement
deletes (opencharly/opencharly#1068). Per the operator's decision, a dropped definition takes its
now-bedless workload image with it.

**What stays, and why.**

- `check-ubuntu-debootstrap-vm` — charly's own proof that the toolchain installs on a from-scratch
  `debootstrap` Ubuntu root (the binary at `/usr/bin/charly`, the welded command plugins dispatching
  project-less, the tailscale apt-repo distro-cascade resolving `ubuntu/noble`), with its
  `ubuntu-debootstrap` fixture.
- The **`githubrunner-ubuntu` cluster** — 2 VM templates, 4 kubevirt vCPU tiers and 3 beds. The
  operator kept it as *package building*: it is the org's live CI fleet on host `no` and the only
  R10 of the `github-runner-ubuntu` candy, which stays.
- `ubuntu`, `ubuntu-builder`, `ubuntu-debootstrap-builder`.

**R5 — the retirement is finished, not partial.** `ubuntu-coder` was named in seven places beyond its
own box and bed; all are updated in this same commit: the `ubuntu-skills` carrier's skill-list prose
and its plan loop, the `ubuntu-builder` skill body (which described itself as *"the multi-stage
builder for Ubuntu-based boxes — currently ubuntu-coder"*), the `ubuntu` skill body (four references,
including the adopt-mode `${USER}`/`${HOME}` example), `AGENTS.md` (skill inventory + R0 load list)
and `README.md` (image table, acyclic-DAG example, carrier description, related-skills list).

**`ubuntu-builder` is not orphaned by this.** The `ubuntu` base declares it in its `builder:` map
(`pixi`/`npm`/`cargo`), so it still serves every Ubuntu-based box needing a multi-stage stage — which
is why the fix was to correct its prose rather than retire it.

### The load-bearing coverage claim, measured

"Every candy the retired demo composed keeps another gate" is what justifies deleting the R10 pod
bed, so it is measured rather than inferred. `ubuntu-coder` composed 26 candies; for each one, is it
still composed by a surviving CachyOS box or bed?

```
$ for c in <the 26 composed candies>; do
    grep -rq "@github.com/opencharly/$c:" distro-cachyos/charly.yml distro-cachyos/box/*/charly.yml && keep++
  done
composed candies: 26
still composed by a surviving CachyOS box/bed: 19
NOT composed by any surviving cachyos box: layer-github-actions layer-google-cloud-npm
  layer-grafana-tools layer-language-runtimes layer-pixi layer-typst pod-sshd
```

**19 of 26 keep an existing gate.** The other seven are `pixi`, `language-runtimes`, `typst`,
`github-actions`, `google-cloud-npm`, `grafana-tools` and `pod-sshd`. The replacement image
`cachyos-coder-tools` (in `opencharly/distro-cachyos`, in flight in its own PR) covers **five** of
those seven: the four candies `pixi`, `language-runtimes`, `typst`, `github-actions`, plus `pod-sshd`
which it composes so the pod has a service.

**TWO ARE NOT COVERED ANYWHERE, and this PR does not pretend otherwise:**

- **`google-cloud-npm`** — its required `layer-google-cloud` cannot complete `install.sh` inside a
  buildkit build container, while the same installer succeeds `rc=0` in a plain container of the same
  base image. A build-venue defect, so no distro choice fixes it:
  **opencharly/layer-google-cloud#5**.
- **`grafana-tools`** — its plan needs `unzip`, the candy declares no `distro:` section at all, and no
  org candy provides unzip for `pac`: **opencharly/layer-grafana-tools#4**.

Both are candy defects owned elsewhere and filed, not caused by this deletion (they equally break the
Fedora/Debian beds that retired in this same campaign).

**Dependency, and its coordination state.** This PR waits on the `cachyos-coder-tools` work tracked
in opencharly/opencharly#1068 (its R10 bed is still running), because landing this deletion first
would leave those candies momentarily unproven — not broken, but unproven — which is the window the
operator's "no unproven window" instruction rules out. The `WAITING` (here) / `HOLDING` (on #1068)
pair is posted.

**And waiting does not close everything**: `google-cloud-npm` and `grafana-tools` stay unproven until
their own candy defects are fixed (the two issues above). That is R1 file-it — a genuinely separable,
externally-owned defect — and it is stated here rather than hidden behind the dependency.
