# 2026.295.2352 — fix(github-runner-ubuntu): one registration script, deploy-time toolchain, no DOCKER_HOST override

## Summary

Make the Ubuntu CI-runner recipe one parameterised recipe that a KubeVirt fleet can actually use,
and fix the three capability gaps a live fleet exposed. Successor to #48 (auto-closed at the org's
five-verdict threshold), carrying the final tree and the findings that closed it resolved.

- **One registration script** (`/usr/local/sbin/charly-register-runners`) replaces four per-unit
  systemd drop-ins and the operator's per-runner `config.sh` calls: `RUNNER_URL`/`RUNNER_ORG`,
  `RUNNER_LABELS`, `RUNNER_GROUP`, `RUNNER_NAME_PREFIX`, `RUNNER_COUNT`, `RUNNER_TOKEN`; idempotent
  (`.runner` is the registration record) and `--remove`.
- **One label source** — the two `/etc/charly-runner-labels*` files are deleted.
- **No `DOCKER_HOST` override.** Measured: with it set, `TestCreateContainerCanMountDockerSocket`
  stopped mounting `/var/run/docker.sock` and the scope test read the engine as podman. Co-tenancy
  is the symlink + heal timer.
- **Deploy-time toolchain.** `distro.ubuntu.package:` is build scope and never reaches a
  prebuilt-disk deploy, so one idempotent deploy step installs node, npm, gh, build-essential,
  skopeo, pip3, unzip, zip, tree, moreutils, bc, less, lsof, strace, netcat, dnsutils, ripgrep and
  ruby, plus a current git (git-core PPA — the provenance tests call `git --no-lazy-fetch`, 2.46+)
  and `shasum`.
- **Warm shared Go cache** per VM (`GOCACHE`/`GOMODCACHE`/`GOPATH`), since the org's workflows pin
  `cache: false` and every job would otherwise start cold.
- **Asserted capabilities** — Chromium's runtime package set (by name), skopeo, ruby, node, gh,
  `br_netfilter` + bridge sysctls, and no `DOCKER_HOST`, each as a runtime check so a missing item
  names itself.
- **Durable image ref** replaces the expiring `ttl.sh` containerDisk.

**No deploy instances.** A deploy names a cluster, a lifecycle and a runner count that belong to an
operator; the repo keeps the recipe, templates and beds, and the fleet lives in a local overlay that
imports this project.

## Root causes (R1)

1. **Four drop-ins for one value** — inert before registration and hardcoded to one org/prefix/count.
2. **A second label source** — `/etc/charly-runner-labels*` duplicated what registration needs.
3. **`distro.ubuntu.package:` is BUILD scope** — measured on a KubeVirt deploy: apt history showed
   only the Docker packages (installed by explicit `run:` steps) and none of the job toolchain.
4. **`DOCKER_HOST` changes what a job observes** — the two tests above.
5. **`ttl.sh` expiry** made the KubeVirt leg irreproducible; a public ghcr ref fixes it.
6. **VM/KubeVirt substrates do not execute candy lifecycle hooks** (only the pod plugin does), so
   registration stays an explicit token-guarded step; the hook gap is filed.

The VMI bed is the one that can catch a deploy-scope gap: it boots a prebuilt disk, so
`distro.ubuntu.package:` is absent and only the deploy-time install counts. Its new
`deploy-scope-toolchain` step asserts node, gh, ruby, skopeo, pip3, unzip, zip, tree and a
Chromium package **by name** — the check that would have caught the Chromium set being in the
wrong scope.

The first bed run after the extraction failed on two assertions that still expected the deleted
drop-ins and label files — an incomplete cutover this change completed in the same phase.

Live fleet (built from this recipe, deploy instances local): three KubeVirt VMs at `nproc=16`, all
twelve runners online, `rg`, `ruby 3.2.3`, `node`, `gh`, `skopeo`, `git 2.55.0`, `shasum` verified in
the guests. A 20-job CI run of `opencharly/crabbox#11` is green on that fleet.
