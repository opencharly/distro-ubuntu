# 2026.325.1116 — fix(ubuntu-skills): drop the copy step; kind:skill installs the owned skills

## Summary

The `ubuntu-skills` carrier drops its `copy: .agents/skills` step, because charly now installs the skills a composed candy owns (opencharly/sdk#598; charly `v2026.325.1102`, opencharly/charly#1230).

That step was resolved against the carrier's own staged directory, so it could never reach the repo-root bodies (opencharly/sdk#444). Its old header said the bodies "live beside this manifest under `.agents/skills`". That was stale: there is no `candy/ubuntu-skills/.agents/skills`, and the six bodies live at the repo root (`.agents/skills/{githubrunner-ubuntu,ubuntu,ubuntu-builder,ubuntu-debootstrap,ubuntu-debootstrap-builder,ubuntu-debootstrap-vm}`), so the step had no source. The rewritten header says where they are. Now `kind:skill` installs the body of every skill an image's composed candies own, at the image user's `~/.agents/skills/<name>/`, through one `COPY` of the owned content. It carries the same set whole in the `ai.opencharly.skill` label.

The carrier keeps its `skill:` routing nodes and its `skill-bodies-installed` ADE `check:`, which proves the bodies landed. Its header comment and `description:` now say whose install it is.
