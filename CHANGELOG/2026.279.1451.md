# 2026.279.1451 — chore(gitignore): ignore the `image/` VM-build scratch dir

## Summary

`charly vm build` writes scratch to `<vm.image_dir>/<vm>/.build.lock`; the default
`vm.image_dir` is `image/`. This repo ignored the sibling `output/` directory but not
`image/`, so a VM build left an untracked `image/` tree that `git status` reported and a
`git add -A` would have staged. `charly/.gitignore` and `distro-omarchy/.gitignore`
already ignore `image/`; this aligns the remaining `distro-*` repos.

Closes opencharly/distro-cachyos#126 (the umbrella issue; the `distro-cachyos` half
lands in its own PR).

## How tested

The path is what `charly vm build` actually writes — observed live on this host during
a `distro-cachyos#125` VM-bed run:

```
$ git -C distro-cachyos status --short     # before the fix
?? image/
$ git -C distro-cachyos status --short     # after adding `image/`
(clean)
```

A full `git check-ignore` proof on each patched tree:

```
$ git -C <repo-worktree> check-ignore -v image/
.gitignore:<n>:image/	image/
```

The change is `.gitignore`-only, so no runtime bed applies; the non-runtime standards
(`charly box validate` is unaffected — `.gitignore` is not a manifest input) hold.
