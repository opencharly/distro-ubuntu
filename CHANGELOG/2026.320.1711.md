restored the section header, `3e20261` removed the bed's own), and the control is one question asked after
every deletion: *does the line above my cut still describe something that exists?*
The skill body is **not** removed here and is not orphaned: it lives with the candy, in
`layer-clawsweeper`, which is where Part II #5 puts it — this repo never owned that prose.

## How tested

The change class is a config deletion (non-runtime), so the gate is validation on the committed tree,
with the counts as the control:

```
$ charly -C … box validate     # BEFORE (origin/main efbe47f)
charly box validate: OK — checked 12 candies, 5 boxes, 5 deploys, 6 distros, 7 builders; 0 warnings, 0 errors
$ charly -C … box validate     # AFTER (head f4cb6c9 — re-run for this round)
charly box validate: OK — checked 10 candies, 4 boxes, 4 deploys, 6 distros, 7 builders; 0 warnings, 0 errors
```

Boxes `5 → 4` and deploys `5 → 4` are the two deletions; candies `12 → 10` is that box's candy closure
leaving with it. Distros and builders unchanged, as they must be.

**The sweep, printed rather than asserted** (a `test -d` loop that prints nothing is not evidence):

```
$ grep -rn clawsweeper --include=*.yml --include=*.md . | grep -vE "CHANGELOG|/\.build/|/\.check/"
SWEEP-MATCHES=0
```

The exclusions are history (`CHANGELOG/`) and generated scaffolding (`.build/`, `.check/`), neither of
which is source; the generated trees still contain the old candy because they are build output that the
next build regenerates.
